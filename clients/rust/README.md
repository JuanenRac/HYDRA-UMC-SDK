# Rust reference client

Real, tested Rust client for the HYDRA-UMC-SDK v1 contracts documented in
[../../docs/CONTRACTS.md](../../docs/CONTRACTS.md): hand-written struct
types plus real JSON Schema runtime validation, mirroring the scope of the
[Python](../python), [Go](../go) and [TypeScript](../typescript) reference
clients for a fourth language.

The published JSON Schema files under `contracts/json-schema/v1/` remain
the **normative source**. Like the Go client (and unlike the Python client,
which hand-reimplements the required v1 subset in pure Python - see
[../../docs/PYTHON_CLIENT.md](../../docs/PYTHON_CLIENT.md)), this crate
compiles and enforces the real schema files directly through a real Draft
2020-12 JSON Schema library, so it validates the full schema, not a
reimplemented subset.

## What's here

- **`src/types.rs`** - hand-written Rust structs for the 7 payload
  contracts (`DeviceDescriptor`, `HealthReport`, `SafetyState`,
  `UpdateManifest`, `EventEnvelope`, `ServerDiscovery`, `ProjectManifest`),
  field-for-field from the schema files. **Not generated by a tool** - no
  `schemafy`/`typify` run; these are written directly against each
  `*.schema.json`'s `required`/`properties`, the same way `clients/go/types.go`
  and `clients/typescript/src/types.ts` are for Go and TypeScript.
  `#[serde(flatten)] extra: BTreeMap<String, serde_json::Value>` round-trips
  unknown fields for the 6 contracts that declare `additionalProperties:
  true`; `ProjectManifest` is the one contract with `additionalProperties:
  false`, so it has no `extra` field and derives `#[serde(deny_unknown_fields)]`
  instead. `NativeVersionPattern` is a real `#[serde(untagged)]` enum for
  `native_version.pattern`'s `oneOf` (a single regex string, or a
  `{major, minor, patch}` object) - Rust's `serde` has native union-type
  support here, unlike Go's `encoding/json` (see
  `clients/go/native_version_pattern.go`). `ContractManifestEntry`/
  `ContractManifest` mirror `manifest.json`'s own shape (the generated
  integrity manifest listing every schema file's sha256 - see
  `contracts/generate_manifest.py`); it is data, not itself a JSON Schema,
  so it has no `validate()` entry point of its own.
- **`src/validation.rs`** - `validate(contract, payload: &serde_json::Value)
  -> Result<(), ContractValidationError>` and `validate_json(contract, data:
  &str) -> Result<(), ContractValidationError>`, both backed by the
  [`jsonschema`](https://docs.rs/jsonschema) crate compiling this crate's
  own vendored copy of each real `*.schema.json` (embedded at **compile
  time** via `include_str!` - this crate's equivalent of Go's `//go:embed`,
  so a built binary needs no access to the monorepo's `contracts/`
  directory at runtime). `should_validate_formats(true)` is set explicitly
  because format validation is draft-dependent and **not** enabled by
  default in this crate - matching Go's `AssertFormat = true` and
  TypeScript's `ajv-formats`, so `format: "date-time"` (used by every
  `timestamp_utc` field) is a real, enforced check. `verify_contract_manifest()`
  is a bonus real integrity check: it recomputes the sha256 (via the
  [`sha2`](https://docs.rs/sha2) crate) of every embedded schema file and
  compares it against `manifest.json`'s own claim for that file.

## Build & test

```bash
cd clients/rust
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

All commands above were run for real against this exact source tree (Rust
1.98.0 on Windows) before this client was committed - `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, and `cargo test --all-targets`
all pass, including:

- `accepts_every_valid_fixture` / `rejects_every_invalid_fixture` - every
  `conformance/fixtures/v1/*.valid.json` and `*.invalid.json` decoded and
  checked against the real compiled schema for its contract, the same
  fixtures `clients/python/tests`, `clients/go/validation_test.go` and
  `clients/typescript/tests/validation.test.mts` all use.
- `vendored_schemas_match_canonical` (`tests/schema_drift.rs`) - proves
  `clients/rust/schemas/*.json` stays byte-identical to
  `contracts/json-schema/v1/*.json`.
- `verify_contract_manifest_passes` - proves every embedded schema file's
  sha256 matches `manifest.json`'s own claim.
- A boolean-is-not-an-integer rejection, an invalid-RFC-3339-date-time
  rejection (proving `should_validate_formats(true)` is really enforcing
  `format`), and an `additionalProperties: false` rejection for
  `ProjectManifest` (the one contract that does not allow extension
  fields) - mirroring the Go and TypeScript clients' own equivalent tests.

## Real, found-and-fixed bug

Writing this crate's own `verify_contract_manifest()` test caught a
genuine, pre-existing drift shared with the Go and TypeScript clients (all
three vendor the same file): `contracts/json-schema/v1/manifest.json`'s
recorded sha256 for `update-manifest.schema.json` was stale - the schema
file itself was edited after the manifest was last regenerated (matching
the SemVer `pattern` addition documented in the root `CHANGELOG.md`'s
`[0.0.5]` entry), but nobody re-ran `contracts/generate_manifest.py`
afterwards. Fixed by re-running that generator and correcting the one
stale digest directly in `contracts/json-schema/v1/manifest.json`; all 7
entries now verify against the real file contents on disk.

A second, Rust-specific issue this crate's own test suite caught:
`manifest.json` (unlike the `*.schema.json` files) is saved with a leading
UTF-8 byte order mark. `serde_json::from_str` does not skip it, so
`load_contract_manifest()` strips it explicitly before decoding - the same
handling Go's `utf8BOM` trim and TypeScript's `stripBom()` already give
their own languages.

## Usage

```rust
use hydra_umc_sdk::validate;
use serde_json::json;

let report = json!({
    "schema_version": "1.0",
    "state": "READY",
    "timestamp_utc": "2026-01-01T00:00:00Z",
    "checks": {"storage": {"state": "PASS"}},
});

match validate("HealthReport", &report) {
    Ok(()) => println!("valid HealthReport"),
    Err(error) => eprintln!("invalid: {error}"),
}
```
