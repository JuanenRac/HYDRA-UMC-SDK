# Go reference client

Real, tested Go client for the HYDRA-UMC-SDK v1 contracts documented in
[../../docs/CONTRACTS.md](../../docs/CONTRACTS.md): hand-written struct
types plus real JSON Schema runtime validation, mirroring the scope of the
[Python reference client](../python) for a second language.

The published JSON Schema files under `contracts/json-schema/v1/` remain
the **normative source**. Unlike the Python client (which hand-reimplements
the required v1 subset in pure Python - see
[../../docs/PYTHON_CLIENT.md](../../docs/PYTHON_CLIENT.md)), this Go
client compiles and enforces the real schema files directly through a real
JSON Schema library, so it validates the full schema, not a reimplemented
subset.

## What's here

- **`types.go`** - hand-written Go structs for the 7 payload contracts
  (`DeviceDescriptor`, `HealthReport`, `SafetyState`, `UpdateManifest`,
  `EventEnvelope`, `ServerDiscovery`, `ProjectManifest`), field-for-field
  from the schema files. Not generated by a tool - written directly against
  each `*.schema.json`'s `required`/`properties`. `ContractManifestEntry`/
  `ContractManifest` mirror `manifest.json`'s own shape (the generated
  integrity manifest listing every schema file's sha256 - see
  `contracts/generate_manifest.py`); it is data, not itself a JSON Schema,
  so it has no `Validate()` entry point of its own.
- **`native_version_pattern.go`** - `NativeVersionPattern` custom
  `MarshalJSON`/`UnmarshalJSON`, because `project-manifest.schema.json`'s
  `native_version.pattern` is a real `oneOf`: either a single regex string,
  or a `{major, minor, patch}` object of three regexes. Go's
  `encoding/json` has no native union-type support, so this is written by
  hand rather than silently picking one shape.
- **`validation.go`** - `Validate(contract string, payload any) error` and
  `ValidateJSON(contract string, data []byte) error`, both backed by
  [`github.com/santhosh-tekuri/jsonschema/v5`](https://github.com/santhosh-tekuri/jsonschema)
  compiling this client's own vendored copy of each real `*.schema.json`
  (embedded at build time via `//go:embed schemas/*.json`, so a built
  binary needs no access to the monorepo's `contracts/` directory at
  runtime). `jsonschema/v5` was chosen over `gojsonschema` because it
  correctly implements the `https://json-schema.org/draft/2020-12/schema`
  draft every one of these files declares; `AssertFormat` is enabled so
  `format: "date-time"` (used by `timestamp_utc` fields) is a real,
  enforced check, not a parsed-and-ignored annotation.
  `VerifyContractManifest()` is a bonus real integrity check: it
  recomputes the sha256 of every embedded schema file and compares it
  against `manifest.json`'s own claim for that file.

## Real, found-and-fixed bug

Running this client's own `VerifyContractManifest()` for the first time
caught a genuine, pre-existing drift: `contracts/json-schema/v1/manifest.json`'s
recorded sha256 for `update-manifest.schema.json` was stale - the schema
file itself was edited after the manifest was last regenerated (matching
the SemVer `pattern` addition documented in the root `CHANGELOG.md`'s
`[0.0.5]` entry), but nobody re-ran `contracts/generate_manifest.py`
afterwards. Fixed by re-running that generator and correcting the one
stale digest; all 7 entries now verify against the real file contents on
disk, and this client's own test suite (`TestVendoredSchemasMatchCanonical`,
`TestVerifyContractManifestPasses`) makes that regression impossible to
reintroduce silently again.

## Build & test

```bash
cd clients/go
go build ./...
go vet ./...
go test ./... -v
```

All commands above were run for real against this exact source tree
(Go 1.26.7 on Windows) before this client was committed. `go build`,
`go vet`, and `go test ./... -v` all pass, including:

- `TestAcceptsEveryValidFixture` / `TestRejectsEveryInvalidFixture` - every
  `conformance/fixtures/v1/*.valid.json` and `*.invalid.json` decoded and
  checked against the real compiled schema for its contract.
- `TestVendoredSchemasMatchCanonical` - proves `clients/go/schemas/*.json`
  stays byte-identical to `contracts/json-schema/v1/*.json`.
- `TestVerifyContractManifestPasses` - proves every vendored schema file's
  sha256 matches `manifest.json`'s own claim.
- Round-trip tests for `NativeVersionPattern`'s two real shapes, and a
  boolean-is-not-an-integer / invalid-RFC-3339-date-time rejection test
  mirroring the Python client's own equivalent tests.

`TestAcceptsEveryValidFixture`, `TestRejectsEveryInvalidFixture`, and
`TestVendoredSchemasMatchCanonical` read `conformance/fixtures/v1/` and
`contracts/json-schema/v1/` from the surrounding monorepo checkout (two
directories up from `clients/go`) and skip themselves with a clear message
if that checkout isn't present - `Validate`/`ValidateJSON` themselves never
depend on it, only on the embedded `schemas/`.

## Usage

```go
package main

import (
    "fmt"

    hydraumc "github.com/JuanenRac/HYDRA-UMC-SDK/clients/go"
)

func main() {
    report := map[string]interface{}{
        "schema_version": "1.0",
        "state":          "READY",
        "timestamp_utc":  "2026-01-01T00:00:00Z",
        "checks":         map[string]interface{}{"storage": map[string]interface{}{"state": "PASS"}},
    }
    if err := hydraumc.Validate("HealthReport", report); err != nil {
        fmt.Println("invalid:", err)
        return
    }
    fmt.Println("valid HealthReport")
}
```
